## M0 工程奠基（第 1 周，11-09 ~ 11-13）

**目标：仓库、环境、密钥安全全部就位，跑通 hello-world 全链路。**

| # | 任务 | 产出 | 验收 |
|---|---|---|---|
| 0.1 | 初始化 git 仓库（根 `.gitignore`、`.env.example`、pre-commit gitleaks 钩子） | 干净仓库 | `git log` 无密钥；故意把 key 写进临时文件，commit 被钩子拦截 |
| 0.2 | Docker Compose：mysql8（ngram 全文）、redis7、pg16+pgvector 三个基础设施容器 + healthcheck + 每日备份脚本 | deploy/docker-compose.yml | `compose up` 后三服务 healthy |
| 0.3 | Spring Boot 骨架：kb-parent 9 子模块、MyBatis-Plus、全局异常/Result/日志 JSON pattern（含密钥脱敏 regex） | backend 可启动 | `GET /api/ping` 返回统一结构；日志不含 Authorization |
| 0.4 | AI 客户端工厂 `AiClientFactory`（读 `AI_API_KEY` 环境变量，构建 LangChain4j Chat/Embedding/Rerank 三个 client）+ 连通性自检端点 `/api/admin/ai-check`（只返回掩码与耗时，不回显 key） | kb-rag 模块 | 调 DashScope 三接口实测 200（chat/embedding/rerank 已预验证可用） |
| 0.5 | Vue3 骨架：Vite+TS+Element Plus+Router+Pinia+axios 拦截器（401→登录）、构建期 `scripts/check-secrets.mjs` 扫描 dist | frontend 可跑 | `npm run build` 后 grep dist 无 `sk-` |
| 0.6 | SQL 迁移：flyway V1 建表（users/kb/documents/chunks/conversations/messages…） | sql/ 迁移脚本 | 全新库一键建表成功 |

**风险**：LangChain4j 对 DashScope 原生 starter 版本兼容性——预案：统一走 OpenAI 兼容端点 `/compatible-mode/v1`（三接口均已实测通过）。

## M2 文档管道：上传→解析→切片→向量化（第 3.5 ~ 6 周，11-24 ~ 12-11）

**关键路径，工期最长。**

| # | 任务 | 验收 |
|---|---|---|
| 2.1 | 上传接口：multipart、扩展名白名单 + Magic Number 双校验、20MB 上限、sha256 秒传去重（同库内） | 伪装 .pdf 的 exe 被拒 |
| 2.2 | 解析策略接口 `DocumentParser`：PDFBox(PDF 含页码元数据)、POI(DOCX 标题层级)、TXT/MD 编码探测+MD 标题结构 | 四类样本文件解析出结构化分段 |
| 2.3 | 切片器：递归分隔符+重叠+token 估算，标题路径/页码写入 chunk 元数据；单测 20 组边界（空文件、纯表格、超长句、全角符号） | chunk 数与覆盖率符合预期，无句子腰斩 |
| 2.4 | 异步处理管道：状态机 UPLOADED→…→READY/FAILED，线程池(并发=2) + Redis 进度（防打爆 DashScope QPS，实测该 key 有限流） | 传 100 页 PDF 轮询看到状态推进 |
| 2.5 | pgvector EmbeddingStore：建 HNSW 索引、批量 embedding(≤10/批)+退避重试、文档删除级联删向量、一键重建索引 | 向量数=chunk 数；删文档向量清干净；429 自动退避 |
| 2.6 | 前端：拖拽上传、状态徽章+进度轮询、失败原因+重试按钮 | UI 走查 |
| 2.7 | 本阶段回归：解析→chunk→向量三表一致性脚本 | 一致性 100% |

**演示物**：上传《XX产品手册.pdf》→ 60 秒后 READY → SQL 里能查到带页码的 chunk 与向量。

## M6 V2 选做（✅ 已于 2026-11-02 完成，详见 docs/05-M6验收记录.md）

- ✅ 分享链接（会话只读分享，token 撤销即 404，不能提问）
- ✅ 重建索引（改切片参数后一键重灌+复问验证）
- ⬜ ES/zhparser 全文升级：当前语料 Recall@5 已 100%，无测量收益，保留为真实环境候选项

## 测试策略贯穿
- 单测：切片器/融合算法/权限判定（核心逻辑 ≥80% 覆盖）。
- 集成：Testcontainers 全栈；文档管道 E2E（真实四类文件）。
- AI 质量：M4 评估集回归（CI 夜间跑，只报不回滚）。
- 手工：每阶段验收 UI 走查清单。

## 每周节奏
周一列任务→周中每日 commit（feat 与 docs 分开提交）→周五演示+更新本表状态列。任一阶段延期 >3 天，优先砍 M4.4 调优实验与 M6，不砍管道稳定性。
