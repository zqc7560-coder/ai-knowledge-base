# RAG 检索质量评估报告

> 对应 docs/02 M4.3/M4.4　日期：2026-11-02　评估脚本：`scripts/eval_rag.py`

## 1. 评估集

30 条问答对，来自 3 篇自造语料（`samples/` + `kb_samples/`）：
- 网关 XG-200 部署手册（14 题）：型号参数、IP/端口、固件版本、灯语、故障排查——含大量**精确 token**（192.168.8.100、V2.3.7、-75dBm），检验混合检索价值。
- 售后质保 FAQ（12 题）：质保年限、退换货、收费——检验数字类事实召回。
- 智能门锁手册（4 题）：续航、指纹容量——早期语料复用。

**指标定义**
- Recall@5：top5 引用片段的文本中包含该题"期望关键词"的比例（检索层质量）。
- 答案正确率：最终回答文本包含期望关键词的比例（端到端质量，含 LLM 生成）。
- 判定词均取自资料原文措辞（首版有 1 题用"不能"而原文是"不支持"，属评测夹具问题，已修正——记录在此避免误读为模型缺陷）。

## 2. 跑分结果（同一评估集，同一 LLM，仅切换检索管道开关）

| 配置 | Recall@5 | 答案正确率 | 平均首响应 |
|---|---|---|---|
| 纯向量（hybrid=off, rerank=off） | 30/30 = **100%** | 30/30 = **100%** | ~2.2s |
| 混合+Rerank（生产默认） | 30/30 = **100%** | 30/30 = **100%** | ~2.2s |

原始日志：`logs/eval-baseline.log`、`logs/eval-hybrid-final.log`。

## 3. 结论与诚实说明

- 两档均满分：当前语料规模（40 chunk / 3 文档）过小，向量检索已能全部召回，
  **混合检索与 rerank 的增益在本评估集上无法体现**——这是样本量决定的，不是功能无效。
- 保留 M4 成果的理由：① 功能开关齐备（kb.rag.hybrid / kb.rag.rerank），大语料下 A/B 即可显效；
  ② RRF/全文通道有独立单测（RrfFusionTest 4 例）与 SQL 层验证（ngram '电池 续航' 命中 4 块）；
  ③ rerank 判别力已单独验证（0.959 vs 0.006，见 docs/01 §6）。
- 生产默认=混合+Rerank 开启：语料增长后（>数百 chunk）纯向量会开始漏召专有名词，
  届时无需改代码。
- 建议后续（M6+）：把评估集扩到 100+ 题、加"干扰文档"（同领域近似内容）制造检索难度，
  才能量化 rerank topK 与 RRF k 值的真实收益。

## 4. 参数调优实验（docs/02 M4.4）

单库默认：chunk 500±100、召回宽K=min(topK*4,20)、rerank 取 topK=5、阈值 0.25、
上下文预算 4000 字符。小语料下调参不敏感（全召回）；维持默认值，理由见 §3。
