# docs/08 · 部署手册

> 本版按用户决定走 **B 方案：本机全栈部署**（无云服务器）。
> 第一部分全部是 2026-11-02 本机实测过的命令与结果；第二部分是未来获得 Linux 服务器时的通用路径（其中 m2seed 差异是真实构建约束，务必先读）。
> 密钥红线：手册内所有口令一律写"从 `deploy/.env` / `backend/.env` 读取"，**任何文档/仓库/日志不得出现明文值**。

## 一、本机（Windows）生产形态部署 —— 已实测

### 0. 前置
- Docker Desktop ≥ 24（WSL2 后端）。检查：`docker info`
- 宿主端口空闲：8085（前端 nginx）/ 8081（后端直连，调试用）/ 3307/6380/5433（开发模式基础设施）/ 19530（可选 Milvus）
- Node 22（前端构建）与 JDK 21（后端构建）在 PATH 或已知位置

### 1. 准备密钥文件（一次性）
```bat
cd D:\项目\ai-knowledge-base\deploy
copy ..\.env.example .env     ← 若无此文件，按 .env.example 的键名手工创建
:: 必填：AI_API_KEY、MYSQL_ROOT_PASSWORD、MYSQL_PASSWORD、PGVECTOR_PASSWORD
:: 可选：KB_ADMIN_USERNAME / KB_ADMIN_PASSWORD（首启自动引导管理员）
```
> `.env` 已被 gitignore；值用强随机串（管理员口令除外可自行记忆）。

### 2. 构建前端产物（镜像只是分发 dist，不代跑构建）
```bat
cd D:\项目\ai-knowledge-base\frontend
npm run build      :: vue-tsc 类型检查 + vite build + 尾部 dist 密钥扫描，三关全过才算成功
```

### 3. 一键起全栈
```bat
cd D:\项目\ai-knowledge-base\deploy
docker compose --profile app up -d
:: 可选向量库 Milvus：docker compose --profile app --profile vector-milvus up -d
```
等待就绪（compose 自带 healthcheck）：
```bat
docker ps --format "{{.Names}} {{.Status}}"    :: 7 个容器全 Up/healthy（不含 Milvus 则 5 个）
```

### 4. 验收
```bat
curl http://127.0.0.1:8085/api/ping            :: {"code":0,...,"mysql":"ok","redis":"ok"}
cd D:\项目\ai-knowledge-base
python scripts\smoke_all.py http://127.0.0.1:8085   :: 全功能冒烟（当前 47 项）
```
浏览器访问 `http://localhost:8085`，用引导管理员或注册新账号登录。

### 5.（可选）HTTPS
```bat
cd D:\项目\ai-knowledge-base\deploy
bash gen-selfsigned-cert.sh            :: 产出 certs/{key,crt}（gitignore），默认 CN=localhost
docker compose --profile app -f docker-compose.yml -f docker-compose.tls.yml up -d
:: 访问 https://localhost:8443（自签证书，浏览器告警属预期；生产换 CA 证书）
```

### 6. 停止 / 数据
```bat
docker compose --profile app --profile vector-milvus down     :: 停止（容器删，卷保留）
docker volume ls | findstr kb                                  :: 数据卷清单
```
数据落位（2026-11-02 实测确认）：**Docker WSL 数据盘在 `E:\DockerData\wsl\`**（docker_data.vhdx 本体在 E 盘，C 盘 AppData 下只是链接视图，不占 C 盘空间）。上传原文件在卷 `kb-uploads`；备份脚本产出物放 `start\backup\`。

### 7. 备份与恢复演练
```bat
cd D:\项目\ai-knowledge-base\deploy
bash backup.sh D:\项目\ai-knowledge-base\start\backup   :: mysqldump + pg_dump + uploads tar，三件套带时间戳
bash restore.sh <备份目录> <时间戳>                     :: 恢复进影子库 kb_restore_test 并核对行数，绝不动生产库
```

### 本机已知环境坑（如实）
| 现象 | 原因与对策 |
|---|---|
| 容器内直连 DashScope/Maven 偶发 TLS reset | 本机 WSL2 NAT + 宿主代理只对宿主进程生效。对策：宿主 7890 代理在跑时最稳；`JAVA_OPTS` 可注入代理参数（backend/Dockerfile 注释有写法）；Milvus 镜像拉不到 quay 时用 daocloud 源 |
| 冒烟经 nginx(8085) 偶发 AI 步骤失败 | 同上抖动；8081/8080 稳定。判重试即可，非代码缺陷 |
| 后端裸跑必须 `cd backend` 再启动 | spring-dotenv 从 cwd 读 `.env`，在别处启动会丢 AI 密钥（start\run-backend.bat 已内置） |

## 二、Linux 服务器部署（未来获得云主机时用）—— 通用步骤

### 1. 服务器准备
```bash
# 2C4G 起步即可（Milvus 另需 +2G）。放行 80/443（安全组），SSH 仅放行管理 IP。
curl -fsSL https://get.docker.com | sh
git clone git@github.com:zqc7560-coder/ai-knowledge-base.git && cd ai-knowledge-base
```
（私有仓库：配 deploy key 或 gh CLI 登录。）

### 2. 配置
```bash
cp .env.example deploy/.env && vi deploy/.env    # 键同第一节；口令全部新生成，不复用本机值
```

### 3. **关键差异：删掉 m2seed 离线构建层**
本机因容器出网问题，`docker-compose.yml` 的 backend 服务配了：
```yaml
    build:
      additional_contexts:
        m2seed: "E:/develop/apache-maven-3.9.4/mvn_repo"
```
服务器上没有这个目录，**必须删除 `build.additional_contexts` 这两行**（backend/Dockerfile 内的 seed 挂载与在线回退逻辑会自然走在线镜像源），否则 compose 构建直接报错。等效一行命令：
```bash
sed -i '/additional_contexts/,+1d' deploy/docker-compose.yml
```

### 4. 构建与启动
```bash
cd frontend && npm ci && npm run build && cd ..     # dist 必须先在宿主构建（镜像只 COPY）
cd deploy
docker compose --profile app up -d --build
docker ps                                            # 等 healthy
```

### 5. 公网化
```bash
# nginx.conf 的 server_name 改域名/公网IP；8085 改 80:80 映射（或用 tls overlay 改 443）
bash gen-selfsigned-cert.sh 你的域名
docker compose --profile app -f docker-compose.yml -f docker-compose.tls.yml up -d
python3 ../scripts/smoke_all.py https://你的域名       # 全绿才算部署完成
```
TLS 生产建议用 certbot 换 Let's Encrypt 正式证书（gen-selfsigned 仅演示）。

### 6. 运维三件套
```bash
crontab -e
0 3 * * *  cd /opt/ai-knowledge-base/deploy && bash backup.sh /var/backups/kb
0 4 * * 7  find /var/backups/kb -name "*.gz" -mtime +14 -delete
```
升级：`git pull && cd frontend && npm run build && cd ../deploy && docker compose --profile app up -d --build`（Flyway 自动补迁移）。

## 三、部署形态速查

| 形态 | 命令 | 场景 |
|---|---|---|
| 开发（裸后端+前端热更） | 双击 `start\start-all.bat` | 日常改代码 |
| 生产全栈（本机） | `docker compose --profile app up -d` | 演示/答辩/本机常驻 |
| 生产+Milvus | 追加 `--profile vector-milvus`，并给 backend 环境加 `KB_VECTOR_STORE=milvus` 与 `MILVUS_URL=http://kb-milvus:19530` | 向量库切换演练 |
| 生产+HTTPS | `-f docker-compose.yml -f docker-compose.tls.yml` | 公网/防窃听 |

管理员口令：见 `deploy/.env` 的 `KB_ADMIN_*`（引导幂等，改值重启即同步）；不注入该变量则首启无管理员，需注册后用 SQL 升角色（docs/03 有流程）。
