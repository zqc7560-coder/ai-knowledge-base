# docs/05 · M6 验收记录（2026-11-02）

> 本文是 M6 全部"选做"项的实现与验收证据。所有数字来自真实运行输出，非计划值。

## 1. 扫描版 PDF 自动 OCR
- 实现：`PdfParser` 检测无文字层→标记 `needsOcr`→`OcrPipeline` 逐页 PDFRenderer(150dpi)→`AiClientFactory.visionChat` 调 `qwen-vl-ocr`→回填文本续走切片/嵌入管道。
- 模型探测定案：当前 key 实测 **qwen-vl-ocr 可用**（中文识别+边界保持），qwen-vl-plus/max 未开通(400 Model not exist)；PaddleOCR 本地方案因容器无法稳定下载模型而放弃，走"接口抽象+API 实现"。
- 护栏：`kb.doc.ocr.enabled/max-pages=30/max-dpi=150`，超限报中文原因入 FAILED（可重试）；开关关闭时同样给明确拒因。
- 测试样本：`samples/扫描版制度手册.pdf`（PIL 渲染中文两页、无文字层、%PDF 魔数合法）。
- 验收（smoke 全绿）：上传→FAILED 原因含"OCR 进行中"→自动转 READY→**基于识别文本问答命中**（"外出服务超出市区 30 公里后每公里加收多少钱"→"20元"+引用）。

## 2. 向量库可切换（兑现 docs/01 的"预留可切换"承诺）
- 抽象：`VectorStore`（kb-rag.vector），`PgVectorStore`/`MilvusStore` 双实现 + `VectorStoreRouter`(@Primary) 按 `kb.vector.store` 分发；上层 RagService/DocumentService/RagPrompts 全部改面向接口（grep 零 Pg 残留）。
- MilvusStore=RESTful v2 轻量适配（零新增依赖），口径**全部实测**：成功码=200（非 0）；`distance` 即 IP 内积；v2.3.16 REST 拒绝显式 HNSW 参数（"only metric type can be passed when use AutoIndex"）→AUTOINDEX+metricType=IP；count(*) 被禁→query 拉 id 计数降级。
- 环境：`deploy/docker-compose.yml` 新增 `milvus`(v2.3.16)+`milvus-etcd`，`profiles: ["vector-milvus"]` 隔离默认栈；`docker compose config` 双 profile 校验通过。
- 演练 A（迁移）：kb15 九片 `pg→milvus`，进度 9/9 DONE；核对 Milvus 该库 9 行、pgvector 该库 0 行（先灌新后清旧语义正确）。
- 演练 B（原生链路）：`KB_VECTOR_STORE=milvus` 独立实例(8089)：建库→上传→READY(9片)→**问答命中 128 台子设备+引用**→Milvus 行数增长。RESULT: PASS。
- 接口：`GET /api/kb/{id}/reindex-status`（active store+任务态）、`POST /api/kb/{id}/migrate?to=`（同目标拒绝、ADMIN 专属、单任务互斥）。

## 3. 重建索引
- 实现：`ReindexService`（专用单线程串行，不与文档管道抢池）：清 chunk+向量→`DocumentService.reprocess`(RUNNING 守卫)重走管道。
- 验收：smoke 中改 chunkSize→reindex→DONE→复问"默认IP"命中 192.168.8.100（参数生效+向量重灌后检索正常的闭环证据）；文档页"重建索引"按钮带进度轮询。

## 4. 答案反馈闭环

## 5. 分享链接（只读）
- `share_links` 表 + SecureRandom token；`POST/GET/DELETE /chat/{conv}/share`，撤销即失效。
- 公开端点 `GET /api/public/share/**`：Sa-Token 白名单 + **无 kbIds**（只回放当时消息快照）——不能提问、看不到库内容，安全模型见 docs/03。
- 前端 `/share/:token` 公开路由（路由守卫放行）+ 生成/复制/撤销/列表 UI。
- 验收（smoke）：创建→匿名读 2+ 条→撤销→再读 1002。
