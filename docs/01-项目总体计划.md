# AI 智能知识库管理系统 — 项目总体计划

> 版本：v1.0　编写日期：2026-11-02　状态：待评审
> 定位：简化版 FastGPT / Dify —— 个人/团队文档知识库 + RAG 智能问答系统

---

## 1. 项目概述

### 1.1 一句话定义
用户上传自己的文档（PDF/Word/TXT/Markdown），系统自动解析、切片、向量化并存入向量数据库；用户随后以对话方式提问，AI 基于其知识库内容检索增强回答（RAG），并保留完整对话历史与知识库权限管理。

### 1.2 目标用户
- 个人：把笔记、书籍摘录、资料文档变成"可问答的第二大脑"。
- 小团队：部门共享知识库（产品手册、制度文档），按成员授权访问。

### 1.3 与 FastGPT / Dify 的取舍
| 能力 | FastGPT/Dify | 本项目（简化版） |
|---|---|---|
| 多知识库管理 | ✅ | ✅ |
| 文档解析+切片+向量化 | ✅ | ✅（PDF/Word/TXT/MD） |
| RAG 问答（流式） | ✅ | ✅ |
| 混合检索 + Rerank | ✅ | ✅（简化实现） |
| 可视化 Flow 编排 | ✅ | ❌ 不做 |
| 插件市场/多模型工作台 | ✅ | ❌ 不做 |
| 团队/部门权限 | 复杂组织树 | 三级角色 + 知识库成员授权（简化） |
| 多租户 SaaS | ✅ | ❌ 单实例部署 |

### 1.4 技术栈总览
| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | Vue 3 + Vite + TypeScript + Pinia + Vue Router + Element Plus + axios | SPA，SSE 流式渲染 |
| 后端 | Spring Boot 3.2.x + Java 17 + MyBatis-Plus + Sa-Token + LangChain4j | 单体分模块（modular monolith） |
| AI 框架 | **LangChain4j**（langchain4j-spring-boot-starter） | 负责 Embedding/Chat/Rerank 调用、文档分块、检索管道 |
| 数据库 | MySQL 8.0 | 业务数据：用户/知识库/文档/对话 |
| 缓存 | Redis 7 | 会话 token、热点问答缓存、任务队列状态、限流计数 |
| 向量库 | **pgvector（首选）** / Milvus（可选，文档量大时切换） | LangChain4j 两者均原生支持，抽象层可切换 |
| AI API | 阿里云百炼 DashScope（OpenAI 兼容模式） | LLM: qwen-plus；Embedding: text-embedding-v3（1024 维）；Rerank: gte-rerank-v2。**密钥仅存服务端**（见 §7） |
| 部署 | Docker Compose | mysql + redis + pgvector + backend + frontend(nginx) |

> 向量库决策：MVP 用 pgvector（一个 Postgres 容器即可，运维成本最低，10 万 chunk 内性能足够）；预留 Milvus Adapter，文档规模 >50 万 chunk 或需要标量过滤复杂查询时切换。LangChain4j 的 `EmbeddingStore` 接口使两者切换只改配置。

## 2. 核心功能需求（按模块）

### F1 用户与认证
- 注册（用户名+邮箱+密码，密码 BCrypt 存储）、登录、登出。
- Sa-Token 会话：token 存 Redis，支持设备踢出、超时续期。
- 三级角色：`ADMIN`（系统管理）/ `KB_OWNER`（创建者，默认所有用户都是）/ `MEMBER`(被授权用户)。

### F2 知识库管理
- 创建/重命名/删除知识库；每个知识库独立配置：切片大小、重叠、Embedding 模型、检索 topK、相似度阈值。
- 知识库列表：文档数、chunk 数、大小、更新时间。
- 权限：私有 / 指定成员（READ、ASK 问答、EDIT 三种授权）/ 团队公开（管理员开关）。

### F3 文档上传与解析
- 支持格式：PDF、DOCX、TXT、Markdown（单文件 ≤20MB，可配置）。
- 解析：
  - PDF → PDFBox（文本型）；扫描版提示 OCR（V2 扩展，MVP 给出明确报错）。
  - DOCX → Apache POI（含标题层级识别，标题作为 chunk 元数据）。
  - TXT/MD → UTF-8/GBK 自动编码探测；MD 保留标题结构。
- 文档状态机：`UPLOADED → PARSING → CHUNKED → EMBEDDING → READY | FAILED`（失败原因可见，支持重试）。
- 上传后异步处理（线程池 + Redis 任务状态），列表实时轮询进度。

### F4 文本切片（Chunking）
- 策略：递归分隔符切分（`\n\n` → `\n` → `。` → `.` → 空格），LangChain4j `DocumentByParagraphSplitter` 定制。
- 参数：目标 chunk 500 token（约 800 中文字符）、重叠 100 token，可按知识库配置。
- 每个 chunk 保存：序号、原文、所在文档 ID、页码/标题路径（供引用溯源）。

### F5 向量化与存储
- Embedding：DashScope `text-embedding-v3`（1024 维，批量 ≤10 条/请求，含重试与限流退避）。
- 存储：pgvector `vector(1024)` + HNSW 索引（`vector_ip_op` 内积，文本做归一化后等价余弦相似度）。
- 删文档 → MySQL 软删 + 向量物理删；重建索引支持按知识库一键重向量化。

### F6 RAG 问答
- 管道：查询 → 向量化 → **混合检索** → **Rerank** → 上下文组装 → LLM 生成 → SSE 流式输出。
- 混合检索：向量 topK(默认20) ∪ 关键词检索（MySQL 全文索引/ LIKE 兜底 → V2 换 ES/zhparser）→ RRF（Reciprocal Rank Fusion）融合 → gte-rerank-v2 重排取 top(默认5)。
- 上下文组装：按 rerank 分数裁剪总 token 预算（≤4000 中文字符），带 `[doc:标题 段落N]` 引用标记。
- Prompt 约束：只根据资料回答、引用标记必须出现在答案中、资料不足时明确说不知道。
- 答案下方展示"引用来源"卡片（文档名 + 原文片段 + 页码），点击跳转原文预览。
- 无召回兜底：告知知识库中未找到相关内容，可切换"联网/通用回答"模式（管理员开关）。

### F7 对话历史管理
- 会话（Conversation）→ 消息（Message）两级；消息记录角色、内容、引用的 chunk ID、token 用量、耗时。
- 多轮：最近 N 轮拼入上下文（默认 5 轮），查询改写（用 LLM 把"它的价格呢"改写成完整独立问题）提升检索命中。
- 会话重命名、删除、置顶；历史记录权限与知识库权限联动。

### F8 后台管理
- 用户管理（禁用/角色）、知识库总览、文档处理任务监控、AI 调用用量统计（按天/按用户）、系统参数（模型、topK、限额）。

## 3. 系统架构

```
┌──────────────┐   HTTPS    ┌─────────────────────────────────────────┐
│  Vue3 SPA    │ ─────────► │                 Nginx                    │
│ Element Plus │  REST+SSE  │   /  → dist      /api → backend:8080     │
└──────────────┘            └──────────────────┬──────────────────────┘
                                               │  (服务端内部网络)
                              ┌────────────────▼──────────────────────┐
                              │        Spring Boot 单体应用            │
                              │  Controller → Service → Repository    │
                              │ ┌─────────┐ ┌──────────┐ ┌───────────┐ │
                              │ │ 认证授权 │ │ 文档管道  │ │ RAG 引擎  │ │
                              │ │Sa-Token │ │解析/切片/ │ │LangChain4j│ │
                              │ │RBAC     │ │向量化异步 │ │检索+Rerank│ │
                              │ └─────────┘ └──────────┘ └───────────┘ │
                              └───┬───────────┬──────────┬─────────────┘
                                  │           │          │ Authorization: Bearer $AI_KEY
                        ┌─────────▼──┐  ┌─────▼────┐  ┌──▼──────────────────────┐
                        │ MySQL 8.0  │  │Redis 7   │  │ DashScope API (百炼)     │
                        │ 业务+全文   │  │会话/任务  │  │ qwen-plus / emb-v3 /     │
                        └────────────┘  └──────────┘  │ gte-rerank-v2 【密钥仅在此】│
                        ┌────────────────┐            └─────────────────────────┘
                        │ Postgres+pgvec │
                        │ HNSW 向量库    │
                        └────────────────┘
```

**要点**：所有 AI API 调用只发生在后端；前端永远只与本系统 REST/SSE 接口通信；密钥经环境变量注入，不出现在任何响应体、日志、前端代码中（详见 §7 密钥安全设计）。

## 5. REST API 设计（v1 摘要）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | /api/auth/register · /login · /logout | 注册/登录（登录限流 5次/分/IP） |
| GET/POST | /api/kb | 我的知识库列表 / 创建 |
| PUT/DELETE | /api/kb/{id} | 改名、参数配置、删除（级联删向量） |
| POST | /api/kb/{id}/members | 授权成员（READ/ASK/EDIT） |
| POST | /api/kb/{id}/documents |  multipart 上传（校验类型/大小/病毒钩子预留） |
| GET | /api/documents/{id}/status | 轮询处理进度 |
| POST | /api/documents/{id}/retry | 失败重试 |
| GET | /api/documents?kbId= | 文档列表（状态、chunk数） |
| POST | /api/chat/conversations | 新建会话（绑定 kbIds，支持多库联合检索） |
| GET/DELETE | /api/chat/conversations/{id} | 历史/删除 |
| POST | /api/chat/ask (SSE) | 流式问答：`{conversationId, question}` → delta/citation/done/error 事件 |
| GET | /api/admin/stats · /api/admin/users | 后台 |

SSE 事件序：`meta`(引用预览) → `delta`×N(增量文本) → `citations`(来源) → `done`(token统计)。

## 6. AI 技术实现方案（深入项）

| 技术 | 实现 | 关键点 |
|---|---|---|
| Embedding | LangChain4j `DashScopeEmbeddingModel`（或 OpenAI 兼容 embedding 端点） | 批大小 10；归一化后点积=余弦；失败指数退避重试 3 次；空文本/超长防御 |
| Chunk | 递归分隔符+重叠；表格/代码块尽量整块保留 | 中文按字符≈token 估算（×0.6），避免切断句子 |
| 向量检索 | pgvector HNSW（m=16, ef=64），`<#>` 内积 | kb_id 过滤下推；相似度阈值默认 0.25 可调 |
| 混合检索 | 向量召回 ∪ MySQL 全文（ngram 中文分词，`MATCH AGAINST`）→ RRF(k=60) | 解决专有名词/编号被 embedding 漏召的问题 |
| Rerank | DashScope gte-rerank-v2，对 RRF 前 20 条重排取前 5 | 已实测：0.96 vs 0.006 判别力良好；rerank 失败时降级用融合分数 |
| RAG Prompt | 系统模板：资料区块 + 引用编号要求 + "资料不足时拒答" | 查询改写（最近 N 轮 → standalone question）；token 预算裁剪 |
| 评估 | 内置 30 条 QA 测试集（自造），跑 Recall@5 / 引用正确率 | 调 topK/阈值/重排开关的依据 |

## 7. API 密钥安全设计（关键约束，专章）

**威胁模型**：密钥泄漏途径 = 前端代码打包、响应透传、日志打印、git 提交、浏览器 DevTools、反编译。逐条封堵：

1. **只存服务端环境变量**：密钥写入 `backend/.env`（加入 `.gitignore`），Spring 用 `AI_API_KEY` 注入；生产用 docker secret / `-e` 传入。**任何代码、配置文件、文档、git 历史均不出现明文。**
2. **前端零接触**：不存在"浏览器直连 AI"的路径；问答走本系统 SSE，前端只见业务数据。
3. **禁止透传与回显**：`@ConfigurationProperties` 绑定密钥的 VO 一律不进 Controller 返回体；`toString()`/日志脱敏（logback pattern 过滤 + 拦截器禁止打印 Authorization 头）；后台"模型配置"页只显示掩码 `sk-ws-****（尾4位）`。
4. **不写入前端构建产物**：Vite 环境变量只允许 `VITE_API_BASE` 这类非敏感项；ESLint 自定义规则 + 构建脚本 grep 扫描 `sk-` 前缀，命中即 fail-build。
5. **git 防线**：`.gitignore` 覆盖 `.env`、`*.local.*`；仓库初始化时即安装 pre-commit（gitleaks 或等价脚本）扫描密钥，防误提交；`.env.example` 只放占位符。
6. **调用面收敛**：只有 `kb-rag` 模块的 `AiClientFactory` 能读密钥并构建 client；Code Review 检查项：禁止在其他模块 `@Value("${AI_API_KEY}")`。
7. **滥用防护（省额度）**：登录用户问答限流（如 20 次/分 + 每日 token 配额，Redis 计数器）；上传文档解析任务全局并发上限，避免批量灌库打爆 embedding 配额。
8. **传输边界**：生产必须 HTTPS（Nginx TLS）；后端→DashScope 走官方域名 TLS。
9. **轮换预案**：密钥集中一处配置；泄漏时改一行环境变量重启即完成轮换；文档记录"该 key 已提交给我看过，上线前必须在控制台重新生成并轮换"（见风险 §9-R1）。

## 8. 非功能需求
- 问答首字延迟 ≤3s，完整答案 ≤30s（P95）；文档 100 页 PDF 处理 ≤3min。
- 并发：MVP 按 50 在线用户设计（Tomcat 200 线程；检索 SQL 走 HNSW；Redis 缓存热门问答）。
- 可用性：单实例可接受（毕设/小团队），MySQL/PG 每日 pg_dump/mysqldump 定时备份进对象目录或 volume。
- 安全基线：密码 BCrypt(10)；登录限流；Sa-Token 会话；上传白名单+Magic Number 校验；SQL 全参数化（MyBatis #{}）；XSS 输出转义（MD 渲染用 markdown-it + DOMPurify）；CSRF（token 走 Authorization header，非 Cookie）。
- 可观测：JSON 结构化日志、按 request-id 串联、AI 调用耗时与 token 埋点（ai_usage_daily）。

## 10. 风险清单
- **R1 密钥已走明文渠道**：该 key 已在聊天中明文出现，**上线前必须在百炼控制台轮换**；本项目按 §7 保证它不再进入仓库/前端/日志。另：该 key 实测有 QPS 限流（429），管道需退避重试与并发上限。

- **R3 pgvector 规模**：>50 万 chunk 后延迟上升 → EmbeddingStore 抽象已预留 Milvus。
- **R4 中文关键词检索**：MySQL ngram 效果一般，V2 上 zhparser/ES。
- **R5 模型额度**：百炼免费额度有限，配额计数 + 掩码用量看板提前预警。
